Each change adds one file under `unreleased/<section>/`, named for its pull request (`45-short-slug.md`), holding one `- **Lead.** Detail.` entry; sections are `breaking`, `added`, `security`, `changed`, `removed`, `fixed`, `tests`, `known-issues` and `internal`. CHANGELOG.md is generated from these files by `scripts/changelog.py` (`just changelog`), so it is never edited by hand. A pull request adds its fragment and leaves CHANGELOG.md alone; the release PR (`just release`) runs `--release X.Y.Z`, which turns `unreleased/` into that version, dates it in `_date` and regenerates the file, so two open pull requests never conflict on it. Prose before a version's sections lives in its `_intro.md`.
